# Docker 완벽 가이드

## 1. Docker의 역사
'내 컴퓨터에선 됐는데?' 문제(환경 차이). 연대기: 2000년대 VM(무겁고 느림) → 2008 Linux 커널 cgroups+namespaces → 2013 Solomon Hykes가 Docker 발표 → 2015 OCI 표준+Kubernetes → 현재 표준. 핵심: Docker는 커널에 이미 있던 격리 기술을 쉽게 포장한 것.

## 2. 작동 원리
VM(각자 OS 전체, 수GB) vs 컨테이너(커널 공유, 앱+라이브러리만, 수십~수백MB, 1초 시작). 3요소: Dockerfile(레시피)→이미지(불변 스냅샷)→컨테이너(실행 인스턴스). 격리=namespaces+cgroups.

## 3. 로컬 vs Docker
`yarn up:infra`가 redis/postgres/rabbitmq를 한번에. 환경 일관성, 버전 충돌 없음, 깨끗한 설치/삭제, 프로덕션 동일성. 'Build once, run anywhere'.

## 4. 포트 매핑
포트 매핑은 Dockerfile에 없다(EXPOSE는 문서용일 뿐). 실제는 `docker run -p` / docker-compose. `-p 8080:3000` = 왼쪽 호스트:오른쪽 컨테이너. 격리된 컨테이너 벽에 창문을 뚫는 것.

# User

namespaces와 cgroups 좀 설명해줘

<!-- kh:msg assistant -->
# Assistant

namespaces=시야 격리('무엇을 볼 수 있는가'), cgroups=자원 격리('얼마나 쓸 수 있는가'). namespaces 종류: PID, NET, MNT, UTS, USER, IPC. PID 예: 호스트 PID 5678이 컨테이너 안에선 PID 1. NET 예: 각 컨테이너가 자기 네트워크 스택을 가져 둘 다 3000 써도 충돌 없음. cgroups: CPU/메모리/IO 제한, `--memory=512m --cpus=1.5`, 초과시 OOM kill. 둘을 합치면 컨테이너.

각 서비스가 3000 쓰겠다 해도 컨테이너 내부적으론 괜찮다는 거구나? 포트를 다르게 할당하는 건가?

<!-- kh:msg assistant -->
# Assistant

오해 교정: 포트를 바꿔치기하는 게 아니라 두 컨테이너가 진짜로 똑같이 3000을 쓴다. 각자 NET namespace가 다르므로 '서로 다른 세상의 3000번'(아파트 101호/102호 1번방). PID와 포트는 별개 namespace. 충돌은 호스트로 포트 꺼낼 때만 → [3000:3000], [3010:3000]처럼 호스트 번호만 다르게.

<!-- kh:msg user -->
# User

net namespace는 정확히 뭐야? 실제 포트 할당은 어떻게 일어나?

<!-- kh:msg assistant -->
# Assistant

NET namespace=네트워크 스택 통째 복사본(인터페이스/IP/포트테이블/라우팅/iptables). 포트 테이블이 namespace마다 따로라 충돌 없음. 실제 포트 할당: app.listen(3000)→bind() 시스템콜→커널이 해당 namespace 포트장부 확인→비었으면 기록, 차면 EADDRINUSE. 바깥 접속: veth pair(가상 랜선), docker0(가상 스위치), iptables DNAT(`-p`가 생성).

osi 7계층에서 각각 어느 계층?

<!-- kh:msg assistant -->
# Assistant

L7 nginx/HTTP, L4 포트/bind()/TCP, L3 IP/iptables NAT(DNAT/MASQUERADE), L2 veth/docker0/MAC, L1 veth 가상랜선. iptables NAT=L3+L4 양다리. OSI 밖: PID namespace/cgroups(OS 격리). NET namespace=L2~L4 스택 통째 복제.

dnat 조작하면 다른 프로그램 망가지겠네? 명령어는?

<!-- kh:msg assistant -->
# Assistant

NAT 테이블 쥔 자가 행선지 장악(root 특권). 명령어 `iptables -t nat -I DOCKER 1 ! -i docker0 -p tcp --dport 8080 -j DNAT --to-destination <B_IP>:80`. 발견: 맥 localhost:8080은 여전히 A(OrbStack docker-proxy가 iptables 우회), VM_IP:8080→B(하이재킹 성공, iptables 경로). -D로 정확히 삭제해 복구.

# User

실생활 공격과 방어는?

<!-- kh:msg assistant -->
# Assistant

본질: 경로 장악=트래픽 장악. 공격: 특권 컨테이너 사이드카 MITM, docker.sock 노출, 메타데이터 하이재킹, ARP/DHCP 스푸핑, DNS/BGP 하이재킹. 방어: 축A 최소권한(no --privileged, cap-drop=ALL, NetworkPolicy, RPKI), 축B 암호화+인증(mTLS/TLS, 장악당해도 무력화, 최고 가성비), 축C 탐지(audit/Falco). 실무: mTLS+NetworkPolicy+특권 금지.
