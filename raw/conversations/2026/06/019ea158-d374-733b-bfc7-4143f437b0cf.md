# User

docker의 역사, 작동원리, 로컬 대비 이점, 도커 네트워크 포트 매핑 설명해줘

<!-- kh:msg assistant -->
# Assistant

Docker 역사: 2000년대 VM→ 2008 Linux cgroups+namespaces→ 2013 Solomon Hykes Docker 발표→ 2015 OCI+K8s. 커널에 있던 격리 기술을 쉽게 포장한 것. 작동: VM(OS 전체, 수GB) vs 컨테이너(커널 공유, 수십~수백MB). Dockerfile→이미지→컨테이너. 이점: 환경 일관성, 버전 충돌 없음, 'Build once run anywhere'(yarn up:infra 예). 포트 매핑은 Dockerfile이 아닌 -p/compose에서, `-p 8080:3000`=호스트:컨테이너, 격리된 벽에 창문 뚫기.

<!-- kh:msg user -->
# User

namespaces와 cgroups 설명

<!-- kh:msg assistant -->
# Assistant

namespaces=시야 격리(PID/NET/MNT/UTS/USER/IPC). PID: 호스트 5678이 컨테이너 안 PID 1. NET: 각자 네트워크 스택, 둘 다 3000 써도 충돌 없음. cgroups=자원 격리(CPU/메모리/IO, --memory/--cpus, OOM kill). 둘 합치면 컨테이너.

<!-- kh:msg user -->
# User

각 서비스가 3000 써도 컨테이너 내부적으론 괜찮다는 거구나?

<!-- kh:msg assistant -->
# Assistant

포트 바꿔치기 아니라 둘 다 진짜 3000 쓴다. NET namespace가 달라 서로 다른 세상의 3000. PID와 포트는 별개 namespace. 호스트로 꺼낼 때만 충돌 → [3010:3000]처럼 호스트 번호만 다르게.

<!-- kh:msg user -->
# User

net namespace는 정확히 뭐고 포트 할당은 어떻게?

<!-- kh:msg assistant -->
# Assistant

NET namespace=네트워크 스택 통째 복사본(인터페이스/IP/포트테이블/라우팅/iptables). 할당: app.listen(3000)→bind()→커널이 해당 namespace 포트장부 확인→기록/EADDRINUSE. 바깥 접속: veth pair, docker0, iptables DNAT.

veth/bridge/NAT 상세히

<!-- kh:msg assistant -->
# Assistant

veth pair=양 끝 뚫린 랜선(eth0↔vethXXX). docker0=가상 스위치/게이트웨이. 나갈 때 masquerade(자동), 들어올 때 -p로 DNAT. veth+bridge=배선, NAT=주소 번역.

# User

osi 7계층 매핑

<!-- kh:msg assistant -->
# Assistant

L7 HTTP, L4 포트/TCP, L3 IP/NAT, L2 veth/docker0/MAC, L1 veth 가상랜선. NAT=L3+L4. OSI 밖: PID namespace/cgroups. NET namespace=L2~L4 통째 복제.

<!-- kh:msg user -->
# User

dnat 조작으로 하이재킹? 명령어?

<!-- kh:msg assistant -->
# Assistant

`iptables -t nat -I DOCKER 1 ! -i docker0 -p tcp --dport 8080 -j DNAT --to-destination <B_IP>:80`. 맥 localhost는 docker-proxy가 iptables 우회라 안 먹히고, VM_IP:8080은 하이재킹 성공. -D로 복구.

<!-- kh:msg user -->
# User

실생활 공격과 방어?

<!-- kh:msg assistant -->
# Assistant

공격: 특권 컨테이너 MITM, docker.sock 노출, 메타데이터 하이재킹, ARP/DHCP/DNS/BGP 스푸핑. 방어: 최소권한(no --privileged, NetworkPolicy, RPKI)+암호화인증(mTLS/TLS)+탐지(Falco). mTLS가 핵심.

# User

MEW 2018 사건과 TLS 방어 코드

<!-- kh:msg assistant -->
# Assistant

MEW: BGP 하이재킹(Route53 DNS)→DNS 스푸핑→피싱→~215 ETH 탈취. 가짜 사이트는 유효 TLS 없어 브라우저 경고→무시한 사람만 털렸다. 데모: CA 서명 정품 vs 자체서명 공격자. curl --resolve(DNS 하이재킹)+--cacert(CA 신뢰). 가짜로 우회도 self-signed 에러로 차단, -k로 검증 끌 때만 털림. 하이재킹=경로 속임, TLS=신원 검증.
