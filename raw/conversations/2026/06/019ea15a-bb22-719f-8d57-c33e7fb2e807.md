# Assistant

Docker를 이해하려면 먼저 **"왜 만들어졌는가"**부터 보는 게 좋습니다.

# 1. Docker가 등장하기 전

예전에는 서버에 직접 프로그램을 설치했습니다.

예를 들어 Node.js 서버를 배포한다면:

apt install nodejs
npm install
npm start

그런데 문제가 있었습니다.

개발자 PC:

Node 18
Ubuntu 22
OpenSSL 3

운영 서버:

Node 16
Ubuntu 20
OpenSSL 1.1

이러면:

내 컴퓨터에서는 되는데 서버에서는 안 됨

현상이 매우 자주 발생했습니다.

# 2. VM(Virtual Machine)의 등장

해결책으로 VM을 사용했습니다.

VM은 OS 전체를 포함합니다.

장점:
- 환경 완전 동일

단점:
- 무겁다
- 부팅 느림
- 메모리 많이 사용

# 3. Docker의 등장

2013년경 Docker Inc.가 Docker를 공개했습니다.

사실 Linux에는 원래부터 컨테이너 기술이 있었습니다.

- namespaces
- cgroups

Docker는 이것들을 사용하기 쉽게 만든 것입니다.

# 4. Docker는 어떻게 작동할까?

Docker는 VM이 아닙니다.

핵심:

커널을 공유한다.

그래서 매우 가볍습니다.

## Namespace

프로세스를 격리합니다.

## cgroups

리소스를 제한합니다.

RAM, CPU 사용량 등을 제한할 수 있습니다.

# 5. Docker Image

Image는 실행 가능한 템플릿입니다.

Ubuntu + Node + npm + source code 등을 하나의 이미지로 만듭니다.

# 6. Docker Container

이미지는 설계도.

컨테이너는 실행된 인스턴스.

Class → Image
Instance → Container

# 7. Dockerfile은 무엇인가?

이미지를 만드는 레시피입니다.

예:

FROM node:22
WORKDIR /app
COPY . .
RUN npm install
CMD ["npm", "start"]

# 8. 로컬에서 직접 실행하는 것과 차이

로컬 실행은 Node 버전, OS, 라이브러리 차이로 환경 불일치 문제가 발생할 수 있습니다.

Docker는 실행 환경까지 포함하므로 개발/테스트/운영 환경을 최대한 동일하게 유지할 수 있습니다.

# 9. 실제 기업들이 Docker를 좋아하는 이유

서비스별로 컨테이너를 분리하여 관리하기 쉽습니다.

API, Redis, PostgreSQL, Worker 등을 각각 독립 컨테이너로 운영할 수 있습니다.

Docker = 컨테이너 실행
Kubernetes = 컨테이너 대규모 관리

# 10. 포트 매핑은 무엇인가?

컨테이너는 자체 네트워크를 가집니다.

컨테이너 내부에서 3000 포트를 열어도 호스트에서는 바로 접근할 수 없습니다.

예:

docker run -p 8080:3000 my-app

의 의미:

Host 8080 → Container 3000

즉 브라우저에서 localhost:8080 으로 접속하면 컨테이너 내부의 3000 포트로 전달됩니다.

# 11. Docker Compose에서 보는 포트

ports:
  - "8080:3000"

역시 Host 8080 → Container 3000 의미입니다.

# 12. Docker의 가장 큰 가치

애플리케이션과 실행 환경을 하나의 패키지로 묶어서 어디서나 동일하게 실행할 수 있게 해준다.

그래서 현대 클라우드 환경에서는 사실상 컨테이너가 표준 배포 단위가 되었습니다.
