아, DNS 얘기였군요. **MX (Mail eXchanger) 레코드**는 상태값이라기보다는 DNS 레코드 타입 중 하나로, **해당 도메인의 이메일을 수신할 메일 서버를 지정**하는 레코드입니다.

구조는 이렇습니다:

```
example.com.    3600    IN    MX    10 mail1.example.com.
example.com.    3600    IN    MX    20 mail2.example.com.
```

- **우선순위 (Priority)** — 앞의 숫자 (10, 20). **낮을수록 먼저 시도**되고, 같은 값이면 부하 분산됩니다. 위 예시에선 mail1이 죽었을 때만 mail2로 갑니다.
- **메일 서버 호스트명** — 반드시 A/AAAA 레코드로 해석되는 호스트명이어야 하고, CNAME이나 IP 직접 지정은 표준 위반입니다.

흔한 사용 예:

| 서비스 | MX 값 |
|---|---|
| Google Workspace | `smtp.google.com` (우선순위 1) |
| Microsoft 365 | `<도메인>.mail.protection.outlook.com` (0) |

확인 방법:

```bash
dig MX example.com +short
# 또는
nslookup -type=MX example.com
```

참고로 메일 관련 DNS 셋팅은 보통 MX만으론 부족하고, 발신 인증을 위해 **SPF**(TXT), **DKIM**(TXT), **DMARC**(`_dmarc` TXT)도 같이 설정해야 스팸 처리를 피할 수 있습니다.

혹시 지금 특정 도메인 MX 설정 중이시면 (예: mvlchain.io 관련) 어떤 메일 서비스에 연결하려는지 알려주시면 구체적으로 도와드릴게요.

## IP Reputation이란

이메일 발송 시 **발신 IP 주소에 대한 신뢰도 점수**입니다. Gmail, Outlook 같은 수신 측 메일 서버(ISP)가 "이 IP에서 오는 메일을 받아줄까, 스팸함에 넣을까, 아예 거부할까"를 결정하는 핵심 기준이에요.

## 평가 요소

- **스팸 신고율 (complaint rate)** — 수신자가 "스팸 신고" 버튼을 누르는 비율. 보통 0.1% 이상이면 위험, Gmail은 0.3% 넘으면 사실상 차단
- **바운스율 (hard bounce)** — 존재하지 않는 주소로 보내는 비율. 리스트 품질이 나쁘다는 신호
- **스팸트랩 적중** — ISP가 심어놓은 미끼 주소로 발송하면 즉시 평판 급락
- **발송량 패턴** — 갑자기 대량 발송하면 의심. 평소 안 보내던 IP가 하루에 수만 통 쏘면 차단됨
- **인증 여부** — SPF / DKIM / DMARC 정합성
- **블랙리스트 등재** — Spamhaus, Barracuda 등 RBL에 올라가 있는지
- **수신자 반응 (engagement)** — 열람, 답장 vs 읽지 않고 삭제

## 공유 IP vs 전용 IP

| | 공유 IP (Shared) | 전용 IP (Dedicated) |
|---|---|---|
| 평판 | 같은 IP 쓰는 다른 발송자들과 **공유** | 내 발송 품질이 곧 내 평판 |
| 적합 | 소량 발송 (월 수만 통 이하) | 대량 발송 (월 10만+ 통, 꾸준한 볼륨) |
| 리스크 | 남이 스팸 쏘면 같이 피해 | 볼륨이 적거나 불규칙하면 오히려 평판 형성이 안 됨 |

SendGrid, AWS SES, Mailgun 같은 서비스가 공유 IP 풀 평판을 관리해주는 게 핵심 가치 중 하나입니다.

## IP Warming (워밍업)

새 IP는 평판이 없어서 **처음부터 대량 발송하면 바로 차단**됩니다. 그래서:

1. 첫날 50~100통 → 며칠마다 2배씩 증가 → 4~8주에 걸쳐 목표 볼륨 도달
2. 워밍업 기간엔 **engagement 높은 수신자**(최근 열람한 유저)에게 먼저 발송
3. AWS SES 등은 자동 워밍업 기능 제공

## 확인 도구

```
- Google Postmaster Tools  — Gmail 기준 IP/도메인 평판, 스팸률 (필수)
- Microsoft SNDS           — Outlook/Hotmail 기준
- Sender Score (Validity)  — 0~100 점수, 80+ 양호
- MXToolbox Blacklist Check — RBL 등재 여부 일괄 확인
- Spamhaus Lookup          — 가장 영향력 큰 블랙리스트
```

## 참고: 요즘은 Domain Reputation이 더 중요

2024년 이후 Gmail/Yahoo 대량발송자 정책 강화로, IP보다 **발신 도메인 평판** 비중이 커졌습니다. IP를 바꿔도 도메인 평판이 나쁘면 소용없어요. 그래서:

- SPF + DKIM + DMARC(`p=none` 이상) 설정은 이제 대량 발송자 **필수 요건**
- 마케팅 메일은 `marketing.example.com` 같은 **서브도메인으로 분리**해서 트랜잭션 메일(영수증, 인증 메일)의 평판을 보호하는 게 정석
- 원클릭 수신거부 헤더 (`List-Unsubscribe`) 필수

특정 서비스(SES, SendGrid 등) 도입 검토 중이거나, 지금 메일이 스팸함으로 가는 문제를 겪고 계시면 상황 알려주시면 그에 맞춰 더 구체적으로 설명드릴게요.
